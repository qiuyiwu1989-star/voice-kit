# 对话模型选型 · 腾讯 TokenHub（2026-09-14）

> 用户拍板：不用 MiMo，统一走腾讯 TokenHub，不同 agent 可以用不同模型，但要保证对话速度。
> 依据：TokenHub 文档（模型列表 / API 协议 / 深度思考）+ 本机实测。**密钥只在 voice-kit/.env。**

## 接入口径

- base_url `https://tokenhub.tencentmaas.com/v1`（广州；备 `.cn`），`Authorization: Bearer`。
- **关思考的通用写法是 `thinking: {"type":"disabled"}`**。`enable_thinking:false` 只有 DeepSeek 认，
  别家照样思考——第一轮基准就是这么白跑的（GLM/Kimi/混元 64 个 token 全被思考吃掉，一个字没出）。
- 前缀缓存 `prompt_cache_key`；`usage.cache_read_tokens` 能看命中。
- 错误码：401002 钥匙无效，402 未开通/欠费，429006 模型忙。

## 哪些能用于实时语音（关得掉思考）

| 模型 | 关思考 | 本机首字（3 次） | 备注 |
|---|---|---|---|
| deepseek-v4-flash | ✅ | 3.1 / 5.1 / 5.1s | 球球生产同款 |
| deepseek-v4-pro | ✅ | 5.2 / 5.6 / 7.9s | 最慢，贵 |
| glm-5.2 | ✅ | 3.4 / 3.9 / 4.0s | 三次最稳 |
| minimax-m3 | ✅ | 3.1 / 3.8 / 5.4s | 不关时把 `<think>` 混进正文，provider 已剥 |
| hy3 | ✅ | 3.4 / 3.5 / 3.6s | 腾讯自家。**别配 `reasoning_effort=low`**：会把思考重新打开、正文为空。首轮那次 SSL 断连是偶发 |
| hy4-preview | ✅ | 429 busy ×2 | 预览版，不能依赖 |
| glm-5.3 / glm-5.3-flash | ❌ 只能 effort=low | 4.2–4.3s，且仍在思考 | 5.3-flash 带 thinking 参数直接 400 |
| kimi-k3 | ❌ 只能 effort=low | 4.2–4.7s，仍在思考 | 后台分析可用，实时不行 |

**⚠️ 这批数字是从本机（跨境）量的，比服务器上高很多**：9-05 在服务器量 deepseek-v4-flash
首字 1.3s，今天本机 3–5s。**排序可信，绝对值不可信。** 上线前要在服务器上重量一次。

## 服务器上的第二批实测（同日晚，每 agent 连打 3 轮）

| 模型 | 首字 | 结论 |
|---|---|---|
| deepseek-v4-flash | 1017 / 1156 / 1204 / 1086 ms | 稳 |
| glm-5.2 | 1164 / 1208 / 1443 / **2872 / 7015** ms | 平均不差，尾部炸 |
| hy3 | 3.2s（上一批） | 慢 |

**语音看尾部不看平均**：三个 agent 全部定 deepseek-v4-flash。差异化留给音色和方法论，不靠模型。

## 三个客户沟通 agent 的分配

| agent | 模型 | 为什么 |
|---|---|---|
| 小安 · 安抚型客服 | hy3 | 客服要稳不要炫；腾讯自家。备选 glm-5.2 |
| 阿询 · 顾问型销售 | deepseek-v4-flash | 追问要有判断力；生产验证过 |
| 大成 · 直达型成交 | glm-5.2 | 三次最稳，风格直 |

三个刻意不同，让「换 agent 换模型」这件事能被亲耳听出来。

## 代码落点

- `providers/tokenhub.py`：`thinking_style="thinking"` 默认通用写法；`reasoning_effort` 透传；流里剥 `<think>`。
- `agents.py`：`MODELS` 表 + `manifest.model` / `reasoning_effort` 校验（配置级 agent 用关不掉思考的模型 = 第一关不过）。
- `service.py`：`/v1/agents/{id}/chat/completions` 的模型跟着 manifest 走。
