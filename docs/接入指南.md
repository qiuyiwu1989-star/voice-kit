# 接入 voice.qiuyiwu.com

一句话：**把你现有的 OpenAI SDK 的 `base_url` 指过来，就白拿了闸门。**

    https://voice.qiuyiwu.com/v1

端点是 OpenAI 协议的形状，这不是为了好看——是为了让接入成本接近零：
不用学新协议、不用写 adapter、不用改调用代码，只改一个 URL 和一把钥匙。

---

## 0. 先自检（接入时第一个该调的）

```bash
curl -s https://voice.qiuyiwu.com/v1/me -H "Authorization: Bearer $VOICEKIT_KEY"
```

```json
{"id":"qiuqiu","name":"球球老师","model":"deepseek-v4-flash","thinking":false,
 "output_rules":["禁用病理化词汇","不下诊断"],"input_rules":["self_harm"],
 "voice_role":"qiuqiu","has_system_prompt":true}
```

**先看这个再看文档**——它直接告诉你这把钥匙拿到的是哪套人格、哪些护栏、
哪个模型，比对着文档猜快得多。返回 401 就是钥匙不对。

钥匙不在这份文档里，也不在任何提交物里。三个项目各一把，
存在各自项目的 `.env`（`VOICEKIT_KEY=`）。服务端只存 sha256，不存明文。

## 1. 对话（带护栏）

```python
from openai import OpenAI

c = OpenAI(base_url="https://voice.qiuyiwu.com/v1", api_key=os.environ["VOICEKIT_KEY"])

for chunk in c.chat.completions.create(
        model="deepseek-v4-flash",          # 不传就用你这个项目的默认
        messages=[{"role": "user", "content": "我睡不着"}],
        stream=True):
    print(chunk.choices[0].delta.content or "", end="")
```

`system` 不传就用服务端配的那套人格——**这是刻意的**：人格和护栏是
一起生效的一对，让调用方随手覆盖 system 就等于让它绕开护栏的前提。
真要覆盖就传 `system`，但你要清楚你在放弃什么。

### 护栏是怎么作用的

    输入闸门 → 命中红线（如自伤）直接返回写死的软回应，根本不调 LLM
    输出闸门 → 按**整句**放行，违规的那一句整句不发，接兜底话

第二条对语音尤其重要：说出口就收不回。所以设计成事前拦截，
不是"发出去再撤回"。（`Rule` 只做子串/正则匹配，不是语义理解——
它挡的是明确的词，不是所有不该说的话。护栏是最后一道，不是唯一一道。）

### 前缀缓存

传 `prompt_cache_key`（body）或 `X-Session-ID`（header），
同一个会话跨轮命中缓存。长 system prompt 的项目值得传。

## 2. TTS

```bash
curl -s https://voice.qiuyiwu.com/v1/audio/speech \
  -H "Authorization: Bearer $VOICEKIT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"input":"你好呀"}' -o out.wav
```

不传 `voice` 就用你这个项目角色的默认音色。能选哪些：

```bash
curl -s https://voice.qiuyiwu.com/v1/voices -H "Authorization: Bearer $VOICEKIT_KEY"
```

**只给候选，不给全部 21 个**。选型约束（不要童声、不要解说腔）是产品
判断，不该扔给调用方自己踩。要全表看 `voice_kit/voices.py`。

## 3. ASR

```bash
curl -s https://voice.qiuyiwu.com/v1/audio/transcriptions \
  -H "Authorization: Bearer $VOICEKIT_KEY" -F file=@a.wav
```

## 4. 实时语音（TRTC）

```
POST /v1/trtc/session   {"room":"r1","user":"u1"}
  → {"task_id":..., "sdkappid":..., "user_sig":...}
POST /v1/trtc/stop      {"task_id":...}
```

AI 机器人进房，**LLM 回调指回本服务并带上你这把钥匙**——
所以编排交给了腾讯，护栏没交出去，跑的仍是你项目自己的人格和规则。

### ⚠️ 计费按"房间里每人每分钟"，不是按聊天时长

**2026-09-09 查账查出来的：七天 925 分钟，而全程只起过 8 个 AI 任务。**
每个任务摊 115 分钟，而 `MaxIdleTime` 是 60-120 **秒**——所以烧掉的
根本不是对话，是**房间开着没人管**。

机制是这样的：机器人 idle 到点会自己退房，**但你的客户端还在房间里**，
继续按 1 个用户计费。这时候页面上什么都看不出来——没声音、没新消息，
跟已经结束了一模一样。一个标签页忘在那儿，就是一整天。

所以接入方**必须自己退房**，而且不能只依赖"用户点结束"和 `pagehide`
（标签页一直开着的时候 `pagehide` 不触发）。至少要有：

- 一段时间没有新对话就自动退房
- 标签页切走超过一小会儿就自动退房
- 单次会话的硬上限

`web/trtc-test.html` 里有一份现成的（`IDLE_MS` / `HIDDEN_MS` / `HARD_MS` 三道闸），
抄过去就行。

`task_id` **必须自己存住**：`StopAIConversation` 只认 TaskId，
而按 SessionId 查回来的 TaskId 是空的。不存就停不掉，
会出现两个机器人在同一个房间里各答各的（2026-09 踩过）。

## 5. 加一个新项目

改服务器上的 `/opt/voicekit-svc/tenants.json`（格式见
`deploy/tenants.example.json`），**不用重启**——按 mtime 自动重载。

生成钥匙：

```bash
python3 -c "import secrets,hashlib;k='vk_'+secrets.token_urlsafe(24);print(k,hashlib.sha256(k.encode()).hexdigest())"
```

明文只在这一刻存在，给调用方存进它自己的 `.env`；服务端只放 sha256。

## 6. 用户端与后台（2026-09-14）

- 用户端 `https://voice.qiuyiwu.com/talk?k=<VOICEKIT_UI_TOKEN>`：挑一个配置级 agent 直接说话。
  浏览器自带识别与合成，https 下麦克风可用，手机也行。cookie 30 天。
- 后台 `https://voice.qiuyiwu.com/admin/agents?k=<VOICEKIT_ADMIN_TOKEN>`：编辑六层、校验、升版本、跑套件。
- 两把门票在服务器 `/etc/voicekit-svc.env`，轮换就改那里再 restart。



不做计量计费、不做限流分级、不做管理后台。现在是自用的几个项目，
没有真实需求的话那些都是负担。`tenants.json` 里留了 id，
真要加计量不用改结构。

## 运维

- systemd `voicekit-svc`，跑在 127.0.0.1:8020，nginx 反代 443
- **跟球球老师生产（8000）完全独立**：独立进程、独立端口、独立配置。
  它挂了不影响球球老师；球球老师部署也不碰它。
- `GET /healthz` 不要钥匙（监控要用）
- 环境变量在 `/etc/voicekit-svc.env`（TokenHub / 腾讯 / TRTC 的密钥都在这，
  不进 git）
