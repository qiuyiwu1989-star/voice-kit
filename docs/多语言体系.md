# 多语言体系：从「语言频道」到「会说多种语言的 agent」

状态：**草案，待用户确认**（2026-09-16）
适用：voice-kit 共性模块、AI 教练、球球老师（儿童端另有约束，见 §7）

---

## 0. 用户的原话和判断

> 我明明选择了英文，但它的 TTS 居然还是中文。
> 目前的多语言其实只是一种频道的形式，但真正的 Agent 应该是「多语」的。哪怕今天是一个英文的 Agent，跟他讲中文，他也会用中文回复。
> 多语言设置只是为了在不同地方推广时更好理解一点。

判断：**对。** 现在的做法是开场前选一个语言，然后界面、听、想、说全部锁死在这个语言上——这是「频道」。
真人不是这样说话的：一个会中英文的教练，你用中文问，他用中文答；你切到英文，他跟着切。
语言设置应该只管**界面和推广包装**，不该管**对话**。

---

## 1. 现状诊断：「选了英文，嗓子还是中文」是三层叠在一起

| 层 | 现在怎么决定语言 | 问题 |
|---|---|---|
| 界面（AI 教练顶栏「中文 / English」） | cookie | **不影响对话**。练习面的语言取壳的 `language` 或地址里的 `?speak=`，所以在顶栏切到 English 再去练，整场还是中文。这是 2026-09-12 有意的设计（练习面跟对话走），但用户感知就是「我选了英文没用」。 |
| 想（模型） | 请求里 `lang=en` 时，系统提示追加「Reply in English」 | **强制**。用户说中文它也答英文。 |
| 说（TTS） | 英文场沿用 agent 的中文音色 | **更正（2026-09-17 实测）**：起初判断是 voice-kit 没传 `PrimaryLanguage`。在服务器上实测腾讯流式合成：同一音色同一段英文，`PrimaryLanguage` 传 1 / 2 / 不传，**音频逐字节相同**，中英夹杂句也一样——这个参数在流式接口上不起作用。「中文嗓子念英文」的真正原因是音色本身是中文播音员。已改为英文场默认给英文音色（`voice_en`，未写则按性别配 WeJack / WeRose）。 |
| 说（音色） | AI 教练 `?v=2` 用 agent manifest 的 `voice`（RED 是 501003）；通用对话页切英文时换成英文音色列表第一个 | 两个入口行为不一致；换音色等于换了一个人。 |
| 听（ASR） | 按会话语言选引擎：`16k_zh` 或英文引擎 | 中途换语言听不懂。 |
| 红线闸门 | 规则是中文正则（「分」「级」「诊断」……） | **风险**。英文里的「8/10」「I'd give you a B」「you might have ADHD」闸门拦不住。频道模式下还能靠「英文场少」侥幸，多语模式下这个口子必须先补。 |

---

## 2. 目标模型：三个语言，各管各的

把「语言」拆成三个互不强制的量：

| 名称 | 谁决定 | 管什么 | 不管什么 |
|---|---|---|---|
| **界面语言** `ui_locale` | 用户偏好 > 浏览器语言 > 推广站点默认 | 按钮、说明文字、agent 显示名和简介、复盘报告的标题栏 | 对话里说什么语言 |
| **对话语言** `turn_lang` | **每一轮由用户这句话决定**（检测出来的，不是设置） | 这一轮模型用什么语言回、TTS 用什么发音规则 | 界面 |
| **练习语言锁** `practice_lang`（可选） | 场景作者或用户**明确要求** | 强制回复语言 | 默认不存在 |

**默认规则（写进平台，不写进每个 agent）：**
1. 用户这一句主要是什么语言，agent 就用什么语言回。中英夹杂时，跟占比多的走；专有名词不算。
2. 用户还没开口时（开场白），用 `ui_locale` 猜。
3. agent 的人设、方法论、策略**只写一份**（作者用自己最顺手的语言写），模型负责跨语言表达。不为每种语言复制一套文件。
4. **例外：练习语言锁。** 典型是「用英文给海外投资人讲路演」——用户就是要练英文，他卡住时冒一句中文，agent 应该用英文接住（必要时一句中文提示后回到英文）。这由场景或用户开关显式打开，不是默认。

> 为什么要有锁：AI 教练里「练英文路演」是真实需求。完全跟随用户的话，他一卡壳说中文，整场就滑回中文，练习目的没了。**跟随是默认，锁是工具。**

## 3. 每一层怎么改

### 3.1 想（模型）
- 去掉「lang=en → Reply in English」这条强制。换成平台统一的一段：
  「用对方最近一句话的主要语言回答；对方混说时跟占比多的语言；不要主动切换语言；专有名词保持原文。」
- 有 `practice_lang` 时换成：「始终用 X 回答。对方用别的语言时，用 X 简短接住并把话题带回 X。」
- `lang` 请求参数改名语义为 `ui_locale`（只做开场白提示），新增 `practice_lang`。

### 3.2 说（TTS）
- **按句选音色**：英文句用 agent 的英文音色，中文句用中文音色。~~逐句传 `PrimaryLanguage`~~——2026-09-17 实测流式接口忽略它，无效。
- **「一个 agent 一个嗓子」暂时做不到**：腾讯的中文大模型音色念英文带中文口音，英文音色目前只登记了 WeJack / WeRose 两个精品档。所以 manifest 分 `voice`（中文）和 `voice_en`（英文）。代价：跟随用户语言时，中英切换会听出换了嗓子；英文场里几个男性 agent 共用 WeJack。**待办**：找腾讯是否有中英双语、口音自然的大模型音色，找到再合并成一个。
- 通用对话页的「切英文就换英文音色列表」改掉：音色选择和语言无关。

### 3.3 听（ASR）
- 优先用**支持中英混说的识别引擎**，不再按会话语言二选一。腾讯侧候选引擎和 TRTC `STTConfig.Language` 能否设成混合，**待实测**（这一条不能凭文档想当然，写进 §8 的验证清单）。
- 检测到的语言随转写一起返回（`lang` 字段），给 3.1 和 3.2 用，别让下游再猜一遍。

### 3.4 红线闸门（**先于放开多语做完**）
- 每个档位的规则补英文版：打分（`\b\d+\s*/\s*10\b`、`score`、`grade`、`rating` + 评价语境）、诊断（ADHD、autism、disorder、depressed…）、病理化词汇。
- 规则按语言分组，闸门对每句先判语言再用对应规则；判不出来两组都跑。
- testkit 红线套件每个用例加英文孪生用例；**英文套件不过的档位，不开放英文对话**（儿童档位尤其）。

### 3.5 记忆
- 事实层：存原文 + `lang` 标记，不翻译存储（翻译会丢细节，且事实层要「原话可追」）。
- 速览卡：模型能读混合语言，不需要翻译；只在卡片标题等平台文字上按 agent 的回复语言出。
- 判断层、复盘：见 3.6。

### 3.6 复盘
- 复盘报告语言 = 这场对话里**用户说得最多的语言**；用户可在复盘页一键切换另一语言（重生成或翻译，标注「译文」）。
- 引用的原话**保持原语言**，不翻译（翻译过的原话不是原话）。

### 3.7 界面与推广（这才是「多语言版本」该管的事）
- `ui_locale` 决定：界面文案、agent 显示名/简介（`name_en` / `blurb_en` 已有）、Agent 中心的「能说」标签、示例开场。
- Agent 卡片上的「中文 / English」语言标签改成**「能说：中文 · English」**，表达能力而不是频道。
- 推广版本 = **地区包**，不是另一套 agent：

| 地区包 | 默认界面语言 | 包装差异 |
|---|---|---|
| 中国大陆 | 中文 | 支付、合规文案、示例用人民币和本土场景 |
| 海外 | English | 支付、隐私条款、示例用美元和海外投资人语境 |

  同一个 agent、同一份人设文件、同一个版本号，在两个地区包里显示不同的名字和示例。
- AI 教练顶栏的语言开关**只切界面**，但练习面要把「对话会跟着你说的语言走」讲清楚（一行说明），并提供「这场只用英文练」的锁定开关。

## 4. Agent 定义要加的字段（manifest）

```yaml
languages: [zh, en]          # 能说的语言，Agent 中心按这个显示「能说」；默认 [zh, en]
practice_lang: null          # 场景级默认锁，一般不写；「英文路演」这类场景写 en
voice: 501003                # 中文音色
voice_en: 101050             # 英文音色（已实现，2026-09-17）
name_en / blurb_en           # 已有，属于界面层
```

validate 增加：`languages` 里有 `en` 的 agent，其档位必须有英文红线套件且通过，否则 fail（入职第三关的一部分）。

## 5. 做的顺序

| 步 | 内容 | 为什么这个顺序 |
|---|---|---|
| 1 | ~~修 TTS 发音参数~~ → **英文场给英文音色**（`voice_en`，已做 2026-09-17） | 用户已经踩到；实测证明参数无效，改走换音色 |
| 2 | **红线闸门补英文规则 + 英文孪生测试** | 放开「跟随用户语言」之前必须先堵口子 |
| 3 | **模型层改成跟随用户语言**，加 `practice_lang` 锁 | 核心体验变化 |
| 4 | **ASR 混说引擎实测并切换** | 依赖实测结果 |
| 5 | **一个 agent 一个双语嗓子**；通用对话页音色与语言解耦 | 身份一致性 |
| 6 | **界面层**：AI 教练顶栏说明、锁定开关、「能说」标签、复盘语言规则 | 呈现 |
| 7 | **地区包**：推广站点默认语言、示例、条款 | 推广时再做 |

每一步都进数据回流：回流日志加 `user_lang` / `reply_lang`，新增一个信号 **「语言没跟上」**（用户说英文、agent 答中文，或反过来且未锁定）。

---

## 6. 不做

- 不为每种语言复制一套人设文件（除非某语言需要文化改写，那是地区包里的 `locale_notes`，不是另一个 agent）。
- 不在转写里自动翻译用户原话。
- 不支持中英以外的语言，直到红线套件有对应语言版本。

---

## 7. 儿童端（球球老师）另说

- 儿童对话**不默认开放英文跟随**。红线（8 铁律、不病理化）目前只有中文规则和中文回归；英文套件没过之前，儿童 agent `languages: [zh]`。
- 儿童学英语是另一种产品形态（练习语言锁 + 教学策略），不在本文范围。

## 8. 待验证（不能凭文档想当然）

1. 腾讯实时语音识别有没有能稳定处理中英混说的引擎；TRTC 对话式 AI 的 `STTConfig.Language` 能否设成混合。
2. ~~`PrimaryLanguage` 是否生效~~：流式接口不生效（2026-09-17 实测，音频逐字节相同）。改为待找：腾讯有没有口音自然的中英双语大模型音色。
3. 模型（deepseek-v4-flash）跟随用户语言的稳定性：连续 20 轮随机切换语言，「语言没跟上」比例。
4. 按句检测语言的误判率（短句「OK」「好的」「yes」这类）。
