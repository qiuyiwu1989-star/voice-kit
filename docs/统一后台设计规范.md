## §1 设计原则

这个后台只做三件事：**管 agent 版本、看用户记忆、审回流提案**。用的人是产品负责人本人和少量运营/内容作者，大多在笔记本上用，一坐就是半小时。原则都从这三件事推出来：

1. **看清版本和状态，再动手。** 每个对象（agent、提案、用户）的头部永远写着：它是谁（id）、现在是哪个版本、处在什么状态（草稿/待审/已发布/只读）。按钮在状态旁边，不在状态前面。改动永远落到某个版本号上，页面上看不到版本号的操作一律不做。
2. **危险程度决定按钮离手多远。** 能撤回的（保存一层文件、编辑事实）就近放；会改线上行为的（发布、回滚、强制发布）放在「门槛说明」之后，要先读到条件才能点；不可恢复的（删用户、删事实、删判断）只放在危险区或行尾溢出位，必须二次确认，删用户要输入 uid。
3. **儿童数据先设防，不靠自觉。** 儿童产品的记忆页整页只读、回流页不采集，这不是「按钮置灰」，而是**不渲染**写操作，并在页头挂常驻只读条说明原因。颜色上「儿童数据」有专门的色，任何地方出现都带盾牌图标。
4. **密度服务于对比，不服务于塞满。** 后台要一屏看完「旧版 vs 提案版」「本周 vs 上周」「事实列表」，所以行高、字号比造物云官网收紧一档；但一屏只有一个主操作，其余全是次级或文字按钮。
5. **系统只标问题，人来拍板。** 回流给的是 flag、分析、提案；页面的措辞和布局都把「发布」留给人：评测结果和门槛先展示，发布按钮后出现，强制发布必须写理由并进审计。

### 2.2 为后台延展的（附理由）

| 延展 | 做法 | 理由 |
|---|---|---|
| **文字色加深** | 浅色 `fg-2` 从 ink 56% 提到 **64%**，`fg-3` 从 40% 提到 **46%**；暗色 `fg-3` 从 28% 提到 **40%** | 实测：造物云浅色 fg2 在 `#F4F5F8` 上只有 3.98:1，fg3 2.5:1。营销页辅助文字少、字大；后台表格里大量 12–13px 的元信息（时间、版本、id），必须过 AA。加深后 fg-2 ≈ 5.0–5.3:1 |
| **语义「字色」单列** | 新增 `--vk-ok-ink #0B7A54`、`--vk-warn-ink #8F5E12`、`--vk-err-ink #B8323B`、`--vk-info-ink #1F5FB8`（浅色） | 造物云的 ok/warn 在白底上只有 3.5–3.6:1，当小字徽章不达标。原色保留给圆点、线条、描边；小字一律用 ink 版（在 10% 浅底上 4.8–5.5:1） |
| **暗色主按钮底** | 暗色主按钮底用 `#5B5FE0`（造物云 accentDeep）而不是 `#7B80FF` | 白字在 `#7B80FF` 上约 3.3:1 不达标，在 `#5B5FE0` 上 5.05:1 |
| **危险按钮底** | 两套主题统一 `#C23A43` | 造物云 err `#D8474F` 上白字 4.26:1 |
| **实底表面** | 卡片、表格、侧栏一律实底：浅 `#FFFFFF`、侧栏 `#ECEEF3`；暗 `#12131C`、侧栏 `#0B0B14` | 造物云暗色卡片是 `white 5.5%` 半透明，靠背后光晕出质感；后台没有光晕，半透明叠三层（页→卡→表格行 hover）后层级糊掉，也让对比度随背景漂 |
| **后台状态色** | 待审 / 已发布 / 草稿 / 已评测 / 已作废 / 已回滚 / 只读 / 儿童数据 / 线上环境，见 §3.1.4 | 造物云没有工作流状态，只有 Core/New/Beta 营销徽章 |
| **儿童数据色** | 洋红 `#B0357F` / 暗 `#F08BC4`，永远配盾牌图标 | 要一眼区别于「危险」（红）和「待处理」（琥珀）：儿童数据不是错误也不是待办，是「受保护」。色相避开四个语义色 |
| **只读色** | 石板灰 `#5B6475` / 暗 `#A3ACBD`，配锁图标 | 只读是中性事实，不应显得像警告 |
| **diff 色** | 增 = ok 10% 底 + ok-ink；删 = err 10% 底 + err-ink；等宽字体 | 造物云无代码对比组件；借鉴通用 diff 约定 |
| **等宽字体** | `ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas` | Space Grotesk 是几何无衬线不是等宽，不能用于 diff、id、YAML 编辑；现有 admin.html 已用 JetBrains Mono |
| **字号收紧一档** | 正文 14（造物云 15/16），表格 13（造物云 13.5），页标题 20（造物云 H1 32） | 后台是扫读，不是阅读 |
| **行高** | 正文 1.6（造物云 1.7），表格/列表 1.45 | 同上 |
| **卡片圆角 12**，弹窗 18 | 造物云卡片 18、玻璃卡 22 | 后台卡片会嵌套（卡片里放表格、diff），大圆角嵌套后内外圆角对不上，浪费角落空间 |
| **按钮高度** | 常规 32px、小号 28px、大号 36px（造物云 11/22 内距 ≈ 42px） | 表格行内要放按钮；44px 命中区由行高补足，见 §8 |
| **z-index 阶梯、布局尺寸** | 见 §3.8、§3.9 | 造物云只规定了导航 z-index 60 |
| **暗色表面也不透明时的发丝边** | 暗色卡片加 1px `white 8%` 描边而不是阴影区分层级 | 暗底上阴影几乎看不见 |

可选参考 `AI 教练/设计系统.html` 与 `tokens.css`：**本版没有借用**。造物云规范已覆盖按钮、表单、表格、反馈、状态；缺的（diff、时间线、状态机徽章、分栏布局）按通用后台做法补齐，上表已注明。

### 2.3 刻意不用的

| 不用 | 理由 |
|---|---|
| 玻璃拟态（backdrop-filter、glassA/B/C、shGlass） | 后台背后没有内容可透；模糊在长列表滚动时掉帧；只保留顶部上下文栏一处轻模糊（与造物云滚动后的 navBg 对应） |
| 「呼吸」底噪、光晕 glow1–3、点阵肌理、Hero 径向渐变 | 分散注意力；工具界面每屏没有「重点区」 |
| 入场动效 700ms、错峰渐显、Hover Lift（卡片上浮 4–12px） | 后台要即时。卡片不是链接时不做悬浮 |
| 1280 居中容器 + 40 页边距 + 12 栏 | 后台是全宽应用壳；内容区用「列表栏 + 详情」的固定/弹性分配，详情内部再限宽 |
| 纵向节奏 96 / 64 | 太松；后台区块间 24–32 |
| 全站唯一 CTA 的实心主色胶囊 + 彩色投影 | 后台主按钮也实心，但不加 `0 8px 20px -8px accent` 彩色投影——一页可能有多个主操作区（不同标签页），投影会抢视线 |
| Display 44–66 字号 | 没有展示标题 |
| 营销徽章 Core/New/Beta | 换成工作流状态徽章 |
| 页脚 | 后台无页脚 |
| Web 字体外链（fonts.googleapis.com） | 约束：零外部 CDN。字体栈里保留 `"Noto Sans SC"`、`"Space Grotesk"` 名字，本机装了就用，没装回落到 PingFang SC / 系统字体。**不打包字体文件**（Noto Sans SC 几 MB，不值得） |

## §3 设计令牌

统一前缀 `--vk-`。**默认暗色**（2026-09-16 拍板，与造物云设计系统页一致）：`vk-admin.css` 里 `:root` 写暗色值，`:root[data-theme="light"]` 覆盖为浅色；三页 `<html>` 默认带 `data-theme="dark"`。**不跟随系统**（不用 `prefers-color-scheme`）。用户手动切换后存 `localStorage['vk-theme']`（`light` / `dark`，读写都包 try/catch），没有手动选择、或读不到存储时一律暗色。

> 下面各表仍按「浅 / 暗」两列列值，值本身没变；变的只是哪一组是默认。原稿选浅色默认、跟随系统，理由是白天办公为主——用户选择和造物云设计系统页保持一致。

### 3.11 共享 CSS 怎么送到三个页面（建议）

**推荐：独立静态文件 + 同源路由。**

- 文件：`voice_kit/static/vk-admin.css`（令牌 + 外壳 + 组件）、`voice_kit/static/vk-shell.js`（渲染左侧导航和顶栏、主题切换、移动端抽屉、`/` 聚焦搜索、toast、确认弹窗、⋯ 菜单，零依赖）。（起草时写的是 `admin_ui/`，实施时放进已有的 `static/`，但**不**走 `/talk/lib` 那条公开路径，只从 `/admin/static/` 出。）
- 版本参数：实施时用两份文件的**内容哈希**（`admin.asset_version()`），不用 git 短 hash——服务器上的代码目录不一定是 git 工作副本。
- 顶栏环境标识：服务端把 `VOICEKIT_ENV`（默认「线上」，本地开发设「本地」）注入到 `<body data-vk-env>`，同样在返回 HTML 时替换 `{{VK_ENV}}`。
- 路由：`GET /admin/static/{name}`，只放行这两个白名单文件名，走和页面一样的门票 cookie 校验（同源请求会自动带 cookie，不用额外处理）；响应头 `Cache-Control: max-age=300`。
- 引用：`<link rel="stylesheet" href="/admin/static/vk-admin.css?v=<git短hash>">`，版本号由 FastAPI 在返回 HTML 时替换 `{{VK_ASSET_V}}`，避免部署后吃缓存。
- 为什么不选「模板注入内联」：三页各 17–31KB，再各内联 ~15KB CSS 没大问题，但浏览器切页时不能复用缓存；而且内联后用浏览器 file:// 直接打开 HTML 调样式反而更难（模板占位符没替换）。
- 兜底：`vk-admin.css` 加载失败时页面仍可用（原生控件样式）——所以 HTML 结构保持语义化，不靠 CSS 才能读懂。

## §5 三个页面的信息架构与布局

通用危险操作放置规则（三页一致）：
- **R1** 不可恢复的删除不出现在对象头右侧的主操作位；放在「危险区」卡片（概览标签底部）或行尾「⋯」菜单里。
- **R2** 危险按钮与主按钮之间至少隔 `--vk-space-6`（24px）或一条分隔线，绝不相邻。
- **R3** 改线上的操作（发布、回滚、强制发布、保存壳绑定）前面必须有一段「会发生什么」的说明文字。
- **R4** 不可恢复 → 输入确认词弹窗；可恢复但影响线上 → 普通确认弹窗写明后果；可随时改回 → 不弹窗，事后 toast 带「撤销」。
- **R5** 儿童/只读场景：危险操作和编辑操作**不渲染**，不是置灰。

### 5.1 Agent 管理 `/admin/agents`

**信息架构**
- 列表：按 `status` 分组（生产 / 草稿），组内按最近修改排序。项：名字、状态徽章、id、版本、四关 x/4。筛选受顶栏产品影响。列表栏顶部「+ 新建 agent」（次按钮，不是主按钮——新建不是高频）。
- 详情头：名字（20/600）· id（等宽）· `v2.1.0` · 状态 · 产品 · 铁律档位 · 模型。右侧：`试聊`（次）、`导出`（文字按钮）。
- 标签：
  1. **概览**：入职四关（步骤条，每关 通过/未过/待跑 + 证据链接）、评估卡（最近一次 testkit：通过率、首字 P50/P90）、壳绑定（多选 chips + 「保存壳绑定」——改线上，前面有说明）。
  2. **六层文件**：左侧竖排子标签 `0 身份 manifest.yaml / 1 人格 / 2 方法论 / 3 策略 / 4 透镜 / 5 铁律（只读，锁图标）`，右侧编辑器（等宽 13px，行号）；编辑器上方一行：文件名、`版本 2.1.0` 输入、「看装配出的 prompt」文字按钮；底部 sticky 保存条：`校验草稿`（次）+ `保存这一层`（主）。校验结果以内联 Alert 出现在编辑器上方。
  3. **测试**：套件选择 + 「跑测试（调用真实模型，约 2 分钟）」主按钮；历史报告表格（时间、套件、版本、结果徽章、首字 P50/P90）。
  4. **试聊**：左对话、右「装配出的 prompt」折叠面板；「清空对话」文字按钮。
  5. **历史**：git log 时间线。
- 危险操作：本页没有删除 agent。「保存壳绑定」算改线上，走 R3，不弹窗但保存后 toast 可撤销。

### 5.2 用户记忆 `/admin/memory`

- 儿童产品：详情头下方常驻**只读条**（儿童色 + 盾牌）：「儿童数据：修改流程还没定，这里只能看，不能改、删、导出。」所有「改/删/导出/删除用户」**不渲染**。

### 5.3 数据回流 `/admin/feedback`

**信息架构**
- 列表：agent 名 · 版本 · 近 7 天回合数 · 问题占比（带迷你条，>15% 琥珀）· 待审提案徽章（有才显示）。儿童档位 agent 显示「⛉ 不采集」儿童色徽章，点进去只有说明。
- 详情头：名字 · id · `v2.1.0` · 时间范围分段控件 `7 天 | 14 天 | 30 天`。
- 标签（对应现在的 ①–⑤，去掉圆圈序号改为标签页）：
  1. **趋势**：4 张指标卡（回合、问题占比、首字 P50、截断率），每张带迷你折线和「较上一周期」；下方主图：回合（主色柱）+ 问题占比（琥珀线）。
  2. **问题回合**：flag 多选筛（按严重度分组：高 / 中 / 弱信号），表格：时间、flag 徽章、用户说、agent 回、行尾「加入用例集」。
  3. **分析**：分析记录列表 + 「开始分析（近 7 天）」主按钮；分析详情里「据此出提案」主按钮。
  4. **提案 · n 待审**（默认打开这个标签，如果有待审）：左侧提案列表窄栏（状态徽章），右侧**版式 C**：
     改了什么 → 文件 diff → 评测对比（指标表 + 逐条折叠）→ **门槛卡** → 发布区。
     - 门槛达标：绿色 Alert「达到发布门槛：红线套件不降、用例集不降」→ `发布为 v2.2.0`（主按钮，按钮文字写出版本结果）。
     - 门槛未达标：琥珀 Alert 列原因 → 发布按钮不渲染主样式；折叠「仍要强制发布」区：勾选 + 理由输入（必填，进审计和 CHANGELOG）→ `强制发布为 v2.2.0`（危险按钮）→ 输入确认词弹窗（确认词 = 提案 id）。

     - 编辑提案全文：diff 下方折叠「编辑提案全文」，保存后状态退回草稿，toast 提示「要重新评测」。
  5. **用例集**：表格 + 行尾「⋯ → 删除」。
  6. **版本历史**：时间线（发布、回滚、强制发布三种节点，强制发布节点带理由原文）。

## §6 组件规范

### 6.1 按钮

| 层级 | 外观 | 用法 | 不该 |
|---|---|---|---|
| 主 `.vk-btn--primary` | 实心 `--vk-accent-solid`，白字，胶囊，32px | 一个视图（一个标签页/一张门槛卡）里**唯一**推进流程的动作：保存这一层、发布为 v2.2.0、跑测试 | 一屏两个主按钮；用在「取消」「导出」 |
| 次 `.vk-btn` | `--vk-surface` 底 + `--vk-border-strong` 描边 | 并列的辅助动作：校验草稿、试聊、导出 | 当危险按钮用 |
| 文字 `.vk-btn--ghost` | 无底无框，`--vk-fg-2` 字，hover `--vk-surface-2` 底 | 行内操作（改、看逐句）、低频（看装配 prompt、清空对话） | 承担唯一出口 |
| 危险 `.vk-btn--danger` | 实心 `--vk-danger-solid` 白字 | 只出现在**确认弹窗里**的最终按钮、强制发布 | 出现在列表行、对象头 |
| 危险描边 `.vk-btn--danger-outline` | 透明底、`--vk-err-ink` 字与描边 | 危险区里触发确认弹窗的按钮（删除这个用户…、回滚…） | 直接执行不弹窗 |

- 尺寸：`sm` 28（表格行内）、默认 32、`lg` 36（弹窗底部）。图标 16px，与文字间距 6。
- 状态：hover 底色加深一档（150ms）；active `translateY(1px)`；focus-visible 焦点环；disabled `opacity .45` + `cursor:not-allowed`，**并在旁边或 title 写原因**；loading 替换左侧图标为 14px 转圈，文字改进行时（「评测中…」），宽度锁定不跳。
- 打真实模型、慢、花钱的按钮，文字里带代价：「跑测试（调用真实模型，约 2 分钟）」。
- 按钮文字需要带「…」时表示点了还有下一步（弹窗）：「删除这个用户…」。

### 6.2 表格

- 密度：默认行高 40（上下 10 + 13px×1.45）；「紧凑」36 可在表头右侧切换，存 localStorage。
- 表头：11px Space Grotesk、`--vk-fg-2`（比造物云 fg3 深，理由见 §2.2）、字距 .06em、`--vk-surface-2` 底、sticky。
- 行线 `--vk-border-soft`；hover 行 `--vk-surface-2`；选中行 `--vk-accent-bg` + 左侧 2px 主色条。
- 数字右对齐 + tabular-nums；id、文件名、版本号等宽；时间「今天 10:42 / 09-13 / 2026-08-02」三段式，悬停出完整时间。
- 排序：只给有意义的列（时间、数字）；表头文字 + 12px 箭头，当前排序列表头文字变 `--vk-fg`，`aria-sort` 同步。默认排序在表头上可见。
- 长文本：单元格最多 2 行省略，点击行展开；不做横向滚动，除非是 diff/逐条对比（外层 `overflow-x:auto`）。
- 行尾操作：最多 1 个文字按钮 + 1 个「⋯」；删除永远在「⋯」里。
- 空状态：表格区域内居中，一句话说为什么空 + 下一步（见 6.11）。筛选导致的空要写「当前筛选下没有…」并给「清除筛选」。
- 不该：斑马纹（和选中色冲突）；给每行都放主按钮。

### 6.3 标签与状态徽章

- 状态徽章 `.vk-badge`：胶囊、11px/600、内距 2px 9px、左侧 6px 图形（点/空心圆/锁/盾/叉）。色见 §3.1.4。
- 普通标签 `.vk-tag`：8px 圆角（和徽章区分：**胶囊 = 状态，方角 = 属性**），`--vk-surface-2` 底，`--vk-fg-2` 字，用于产品、铁律档位、shell、flag 名。
- flag 标签按严重度：高 = err、中 = warn、弱信号 = 中性。
- 计数徽章：导航和标签页上的「3」「1 待审」，最小宽 18、高 18、`--vk-warn-bg` + `--vk-warn-ink`（因为只计待办）。
- 不该：一行超过 3 个徽章；用徽章写句子；只有颜色没有字。

### 6.4 表单与内联编辑

- 输入框 32 高、8 圆角、`--vk-surface` 底、`--vk-border-strong` 描边；聚焦主色描边 + 3px 光环（造物云）。
- label 在上方，12px/500 `--vk-fg-2`；帮助文字在下方 12px；错误时描边 `--vk-err`、帮助文字换成 `--vk-err-ink` 的修复说明。
- 编辑器（六层文件、提案全文）：等宽 13px/1.6、`--vk-surface-2` 底、行号列 `--vk-fg-3`、tab 2 空格、最小高 50vh；右上角显示「未保存」小点。
- 内联编辑（事实「改」）：点「改」→ 行变成输入 + `保存` `取消` 两个 sm 按钮，Enter 保存、Esc 取消；保存成功行底闪一次 `--vk-ok-bg`（250ms），并 toast「已改，审计已记录」。复杂字段（多行）才用弹窗。
- 不该：失焦自动保存（事实改动要进审计，必须显式）；placeholder 代替 label。

### 6.5 diff 视图

- 头部：文件名（等宽）+ `+6 −3` 统计 + 右侧「并排 | 合并」分段控件。
- 行：等宽 12.5/1.6，行号两列各 40px，`+`/`−` 符号列 16px（颜色之外的第二通道）；新增行 `--vk-diff-add-bg`，删除行 `--vk-diff-del-bg`，行内词级变化再叠 `--vk-diff-word-*`。
- 未变的连续段 >6 行折叠为「⋯ 展开 18 行未改动」。
- 并排时左旧右新，两栏同步滚动；中文长行软换行，不横滚。
- 不该：用红绿之外的颜色表示增删；把 diff 放进弹窗。

### 6.6 指标卡与迷你折线

- 卡：`--vk-surface` + 1px 边、12 圆角、内距 16。结构：kicker（`TURNS · 回合`）→ 大数字 24/600 Space Grotesk → 变化（`↑ 12% 较上周`，好坏色 + 箭头）→ 迷你折线（高 28，全宽）。
- 「好坏」由指标定义决定而不是涨跌：问题占比涨 = err-ink，回合涨 = ok-ink；持平写「持平」用 `--vk-fg-2`。
- 迷你折线：1.5px 线、主色（或 warn 用于问题类），最后一个点 3px 实心圆；无坐标轴、无网格；`<svg role="img" aria-label="近 7 天回合 52, 61, …">`。
- 主图：柱 = 主色 80% 不透明，线 = warn，网格 `--vk-chart-grid`，坐标 11px Space Grotesk `--vk-fg-2`；图例写在图上方，不用悬浮才能读的图例。
- 不该：一排超过 4 张卡；用饼图；小数点后超过 1 位。

### 6.7 审计时间线

- 竖线 1px `--vk-border`，节点 8px 圆：普通 `--vk-fg-3`、写操作 `--vk-accent`、删除 `--vk-err`、发布 `--vk-ok`、强制发布 `--vk-warn` 空心加粗。
- 每条：时间（12px 等宽，左）· 主体句（14px：「**qiuyiwu** 改了事实 #4」）· 前后值（`旧 → 新`，删除线 + 新值）· 来源（页面 / API / 采样链路）。
- 按天分组，组头 kicker `2026-09-15 · 周二`。
- 不该：只写「更新了记录」；把前后值藏进悬浮。

### 6.8 确认弹窗

- 480 宽、18 圆角、`--vk-shadow-2`、遮罩 `rgba(7,7,15,.48)`；标题 16/600 用问句写结果：「删除用户 u_8f3a21c9？」；正文写**会发生什么 + 什么不会发生 + 能不能恢复**。
- 危险且不可恢复：正文下方输入框，label「输入 `u_8f3a21c9` 确认」，确认词等宽高亮；完全一致前最终按钮 disabled；不允许粘贴限制（运营要能粘贴 uid），但要求完全一致含大小写。
- 按钮：右下，`取消`（次）在左，最终按钮（危险）在右，中间 12；**初始焦点在取消**；Esc = 取消；Enter 只在确认词输入正确后触发。
- 最终按钮文字写结果：「永久删除」「强制发布为 v2.2.0」「回滚到 v2.1.0 内容」，不写「确定」。
- 用原生 `<dialog>`（现有三页已在用），不自造焦点陷阱。

### 6.9 只读提示条

- 位置：详情头下方、标签条上方，全宽，常驻不可关闭。
- 外观：12 圆角、`--vk-st-child-bg`（儿童）或 `--vk-st-readonly-bg`（一般只读）、左侧 16px 盾牌/锁图标 + 粗体标题 + 一句原因。
- 文案必须回答「为什么只读 / 到什么时候」：「儿童数据 · 只读　修改流程还没定，这里只能看，不能改、删、导出。」
- 不该：用琥珀/红色（不是错误）；只在点了按钮后才提示。

### 6.10 Alert（页内常驻提示）

info / ok / warn / err 四种，12 圆角，图标 + 文字，用于校验结果、门槛结论、分析失败。可带一个文字按钮（「重跑」「清除筛选」）。

### 6.11 空状态与加载

- 空状态：一个 24px 线性图标（`--vk-fg-3`）+ 一句事实 + 一个下一步按钮（次按钮）。例：「这个 agent 近 7 天没有回合。换成 30 天看看？ [看 30 天]」「还没有提案。先跑一次分析。 [开始分析]」。
- 首次加载：骨架（列表 6 行灰条、详情头 + 两张卡轮廓），扫光 1.2s，reduced-motion 下静止。
- 局部慢操作（跑测试、评测，可能 1–3 分钟）：按钮 loading + 卡片内进度说明「正在跑 24 条用例 · 已完成 9」；不做全屏遮罩，允许去看别的标签。
- 请求失败：在原位置显示 err Alert「没加载出来：<后端原因>。 [重试]」，不清空已有内容。

### 6.12 Toast

- 右下角，距边 24，宽 ≤ 360，`--vk-surface` + `--vk-shadow-2` + 12 圆角，左侧 3px 语义色条；进出 250ms 上移渐显。
- 成功 4 秒自动消失；带「撤销」的 8 秒；错误**不自动消失**（错误应首选页内 Alert，toast 只用于后台任务完成后的通知）。
- 同时最多 3 条，新的在下。`role="status"`（成功）/ `role="alert"`（错误）。
- 不该：用 toast 报告需要用户读懂才能继续的信息（用 Alert）。

## §7 文案与语气

沿用造物云：**专业、笃定、说人话**；中文弯引号“”或直角「」（后台沿用现有三页的「」）；不用 emoji；不喊口号。后台加这些规则：

1. **按钮写动作的结果，不写动作的类型。** `发布为 v2.2.0` 而不是「提交」；`保存这一层` 而不是「保存」；`强制发布为 v2.2.0` 而不是「确定」；`回滚到 v2.1.0 的内容` 而不是「回滚」。
2. **慢和贵写在按钮上。** 「跑测试（调用真实模型，约 2 分钟）」。现有「打真模型，慢」口语可保留一个过渡期，终态统一为「调用真实模型」+ 预计时长。
3. **错误说怎么修，不说「失败」。** ✕「保存失败」 → ✓「没保存：persona.md 第 12 行 YAML 缩进不对，改成 2 个空格再保存。」✕「401」 → ✓「门票过期了。在地址后面加 `?k=<门票>` 重新进来。」
4. **状态用名词，操作用动词。** 徽章「待审」「已发布」；按钮「审这个提案」「发布」。不混用。
5. **儿童数据措辞。**
   - 统一叫「儿童数据」，不叫「未成年人信息」「小孩隐私」。
   - 说原因，不说禁止：「修改流程还没定，先只读」，不写「无权限」「禁止访问」。
   - 回流页：「儿童档位不采集：不记原话、不分析、不出提案。」
   - 任何地方不对孩子下判断词（沿用球球老师 8 铁律的非病理化原则）；后台示例数据、占位文本里也不写「问题儿童」「注意力差」之类。
6. **审计写法：谁 + 做了什么 + 对哪条 + 前后值 + 为什么（有就写）。** 「qiuyiwu 改了事实 #4（融资阶段）：天使轮 → 天使轮，目标 300 万」「qiuyiwu 强制发布 red-coach v2.2.0。理由：红线套件差 1 条是用例本身过时，已另开任务修。」不写「更新了数据」。
7. **数字带单位和对照。** 「首字 P50 820ms（上周 910ms）」，不孤立给数。
8. **确认弹窗三句话：** 会发生什么 / 什么不会变 / 能不能恢复。
9. **不用「您」**，用「你」或省略主语（沿用现有三页）。

## §8 可访问性与质量底线

1. **对比度**：正文、表格、按钮文字 ≥ 4.5:1；大数字（24px/600）和图形元素 ≥ 3:1。§3 所有「ink」令牌已实测（浅色在白/10% 浅底上 4.8–7.0:1，暗色 5.3–7.7:1）。`--vk-fg-3` 只有约 3:1，**只准用于占位符、禁用、装饰分隔**。
2. **颜色不作唯一信号**：状态徽章有图形 + 字；diff 有 `+/−` 符号列；指标变化有 ↑↓ 箭头；门槛结论有 ✓/! 图标 + 文字。
3. **焦点可见**：全局 `:focus-visible { outline:2px solid var(--vk-accent); outline-offset:2px }`，禁止 `outline:none` 不给替代。暗色下 `#7B80FF` 在 `#07070F` 上 6.1:1。
4. **键盘**：
   - `Tab` 顺序：左侧导航 → 顶栏 → 列表 → 详情。首个可聚焦元素是「跳到主内容」链接。
   - 列表：`↑/↓` 移动、`Enter` 打开（`role="listbox"` 或按钮列表 + `aria-current`）。
   - 标签页：`←/→` 切换，`role="tablist"`。
   - `/` 聚焦搜索；`Esc` 关闭弹窗/抽屉；`⌘/Ctrl+S` 在编辑器里保存这一层（显示在按钮 title）。
   - 确认弹窗初始焦点在「取消」。
5. **命中区**：可点元素最小 32×32（桌面工具取舍，低于造物云 44）；行尾「⋯」按钮实际热区 32×32；移动端（<768）所有可点元素 ≥ 44×44。
6. **减少动效**：`prefers-reduced-motion` 下所有过渡 0ms，骨架不扫光，同步滚动保持（功能性）。
7. **语义与读屏**：页面有 `<nav aria-label="后台模块">`、`<header>`、`<main>`；状态徽章文字对读屏可读（图形 `aria-hidden`）；图表 `role="img"` + 数据摘要；toast `role="status"`。
8. **质量闸（实施时加进 CI 前端闸门）**：三页都只引用 `/admin/static/vk-admin.css`；grep 不允许出现 `#hex` 颜色硬编码（`vk-admin.css` 除外）；不允许 emoji 出现在按钮文字里；不允许外部 `http(s)://` 资源。
