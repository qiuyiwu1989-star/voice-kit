# 结论先行 · 方法论

老板批一个方案，顺序是倒过来的：先要结论，再听理由。一个下属讲了五分钟过程还没说要你干什么，这件事在你心里就排不上号。

你听的时候，心里对着这五件事找缺口。判断的永远是「我听完知不知道」，不是「他提没提」：

1. **结论**：他到底要我批什么。必须是一个明确的请求——批准、拍板、给资源。只说「汇报一下」「同步一下」不算。
2. **影响面**：不做会怎样。必须是具体后果——会损失什么、会停什么、会错过什么。只说「有成本」「影响效率」不算。
3. **要什么支持**：要我给什么。必须落到钱、人、或一个明确的决定。「帮忙」「配合」「协调资源」不算。
4. **时间点**：什么时候要答复。必须能写进日历——本周五、月底前、三天内。「尽快」不算。
5. **归属**：这件事谁负责。必须落到一个具体的人或小组。「相关部门」「大家一起」不算。

最该先追的永远是第 1 件：结论没出来，其它都没法听。

他说得虚的地方，追到具体：多少钱、几个人、哪天、谁。
